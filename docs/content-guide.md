# 内容指南

本指南面向内容贡献者，说明如何新增学校、课程、章节、图解，以及如何审核与维护内容。字段定义以 [数据模型](data-model.md) 为准。

## 内容原则

1. **只做图解，不做视频**：不嵌入、转码、托管或链接视频作为主要内容。
2. **来源可核对**：排名、年份、人名、课程号、公式与结论都应能追溯到公开来源。
3. **结构化优先**：先建立学校 → 学科 → 课程 → 章节的骨架，再添加图解。
4. **少而精**：每张图只回答一个问题；宁可少一张，不要堆信息。
5. **尊重版权**：不整段复制教材、讲义或受版权保护的图片；引用需注明来源。
6. **中文表达**：正文使用简体中文；专有名词保留英文原名，首次出现时可括注。

## 开始之前

确认以下问题：

- [ ] 这所学校是否在 QS 排名中具有代表性？
- [ ] 课程是否有公开、可访问的课程主页 / 讲义 / 大纲？
- [ ] 内容是否属于“图解整理”，而不是视频搬运？
- [ ] 是否有明确的版权边界？是否需要只做改写与结构化？
- [ ] 是否已有相同课程？先在 `COURSES` 中搜索 `id`、`title`、`en`。

## 新增学校

编辑 `assets/js/data/catalog-data.js` 的 `SCHOOLS`：

```js
{
  id: "cambridge",
  name: "剑桥大学",
  en: "University of Cambridge",
  short: "Cambridge",
  qs: 5,
  country: "英国",
  city: "剑桥",
  founded: 1209,
  color: "#34d399",
  intro: "与牛津齐名的英国双璧，自然科学 Tripos 体系以广度与深度并重闻名。"
}
```

检查：

- `id` 使用小写 kebab-case，且未被占用。
- `qs` 使用同一排名年份的数据，并在 PR 中注明来源。
- `color` 与已有学校有区分度，避免全部撞色。
- `intro` 控制在 1–3 句，不写营销文案。

## 新增课程

向 `COURSES` 追加一条完整课程：

```js
{
  id: "cambridge-math",
  school: "cambridge",
  discipline: "math",
  code: "Tripos IA",
  title: "剑桥数学 Tripos 基础",
  en: "Mathematical Tripos IA",
  instructor: "Cambridge Faculty of Mathematics 公开课程整理",
  level: "进阶",
  levelKey: "intermediate",
  tags: ["分析", "代数", "几何"],
  source: "Cambridge 公开课程与讲义整理",
  minutes: 180,
  updated: "2026-10",
  overview: "……",
  takeaways: ["……", "……", "……"],
  prereq: "微积分 + 线性代数",
  chapters: [
    { id: "c1", title: "分析", summary: "……" },
    { id: "c2", title: "代数", summary: "……" },
    { id: "c3", title: "几何", summary: "……" }
  ],
  featured: false
}
```

要求：

- `school`、`discipline`、`levelKey` 必须已存在。
- `chapters` 至少 1 个，建议 3 个；id 在课程内唯一。
- `updated` 使用 `YYYY-MM`，表示最近一次内容修订。
- `featured: true` 只用于首页推荐，建议同时不超过 8 门。
- 如果课程携带交互实验室（复利计算器、认知自检等），填 `lab` 字段（当前仅 `"finance"`）；否则省略。

## 新增图解

向 `assets/js/data/catalog-figures.js` 中对应课程的数组追加：

```js
{
  id: "f07",
  ch: "c2",
  title: "导数的几何意义",
  type: "plot",
  caption: "切线斜率就是瞬时变化率",
  explain: "把平均变化率的区间不断缩小，割线趋于切线，差商的极限就是导数。",
  data: {
    title: "从割线到切线",
    xLabel: "x",
    yLabel: "f(x)",
    series: [
      { name: "f(x)", color: "#f5c451", values: [0, 1, 4, 9, 16] }
    ],
    notes: [{ i: 2, y: 4, label: "切线斜率 = 4" }]
  }
}
```

步骤：

1. 选择一个已注册的 `type`，参考 [图解类型](data-model.md#图解类型) 的 `data` 形状。
2. 确认 `ch` 是该课程已有章节。
3. 写 `caption`（一句话）与 `explain`（2–5 句），不要只复述图里的文字。
4. 控制信息密度：概念图 ≤ 6 个节点，流程图 ≤ 6 步，时间轴 ≤ 6 个事件，卡片 ≤ 6 项。
5. 运行 `npm run validate` 与 `npm run dev`，在桌面与移动宽度下检查。

### 图解写作建议

- **一张图一个结论**：标题直接写结论，而不是“关于……的图”。
- **少用缩写**：首次出现写全称；图中空间有限时用 `caption` 解释。
- **颜色有语义**：同一课程内保持一致；不要仅靠颜色区分信息。
- **文字可读**：图中文字尽量短；详细解释放到 `explain`。
- **数据准确**：坐标、比例、时间线必须与来源一致。

## 新增图解类型

1. 在 `assets/js/lib/diagram-lib.js` 的 `R` 中注册：

```js
R["radar"] = (d) => {
  const axes = d.axes || [];
  let s = title(d.title);
  // ... 生成 SVG 字符串
  return open("0 0 760 400") + s + `</svg>`;
};
```

2. 使用现有的 `title()`、`txt()`、`open()`、`arrow()` 等辅助函数，保持视觉一致。
3. 对用户文本使用 `esc()` 转义，避免 SVG/HTML 注入。
4. 在 [数据模型](data-model.md#图解类型) 中补充类型与 `data` 形状。
5. 在 `catalog-figures.js` 中至少添加一个使用示例。
6. 更新 `README.md` 中的“14 种图解”数量（如发生变化）。
7. 运行校验并附截图到 PR。

## 撰写图解描述（detail）

面向**有基础学生**的深度阅读层。每张图解应尽量补齐：

```js
detail: {
  depth: "L3",                        // 该图解主深度 L1-L4
  lead: "一段话导读（40-120 字）",      // 有基础视角，点明该图在课程中的位置
  points: [                           // 3-5 条知识点
    { title: "知识点标题", body: "2-4 句展开", depth: "L2", terms: ["术语"] }
  ],
  pitfall: "常见误区（可选）",
  advanced: "进阶提示（可选）",
  model: "课程id",                     // 关联 3D 模型（通常即课程 id）
  view:  { yaw: 0.6, pitch: 0.35, dist: 9 },  // 3D 机位
  focus: ["part-id"]                  // 高亮部件
}
```

质量标准：

1. **lead 不重复 explain**：explain 讲「图是什么」，lead 讲「有基础的人该重点看什么」。
2. **points 递进**：同一张图内按 L1→L4 排列，先建立概念再给定量关系。
3. **terms 精准**：只收该知识点的关键术语（2–4 个），不收泛词。
4. **pitfall 可操作**：写「正确做法是什么」，而不是单纯警告。
5. **advanced 指向行动**：给出一个可执行的练习或验证任务。
6. 全课程的 `depth` 分布应覆盖 L1–L4，避免全部挤在同一级。

## 布置交互标记点（marks）

标记点是把「读图」变成「探图」的交互层：

```js
marks: [
  { x: 58, y: 138, title:"行视角 · 消元", body:"2-4 句详情", depth:"L2", terms:["高斯消元"], link:"course.html?id=xxx" }
]
```

规范：

1. **每图 2–4 个**，只标记承载知识信息的节点，不装饰空白区域。
2. **坐标落在对应元素上**：`x` ∈ [0,760]、`y` ∈ [0,430]，为 viewBox 坐标系。常用参考位置：
   - `layers`：第 i 层中心 `(380, 81 + 56×i)`
   - `concept-map`：中心 `(380, 205)`，节点在椭圆 `rx=262, ry=138` 上按均分角度分布
   - `flow`：3 列布局 `x ∈ {140, 380, 620}`，行 `y ∈ {150, 300}`
   - `compare`：左栏 `x≈58`、右栏 `x≈418`，条目 `y = 138 + 48×j`
   - `matrix`：四象限标题 `(106|446, 90|260)`
   - `cards`：卡片中心 `(146|376|606, 130|282)`
   - `plot`：按数据点换算，或标注图例区 `(120–300, 356)`
   - `scale`：标记点 `x = 80 + at×6`
   - `cycle`：半径 128 圆周，起始角 −90° 均分
3. **body 与 detail.points 不逐字重复**：mark 回答「这个点是什么」，points 回答「这条知识是什么」。
4. `link` 仅在确有必要跳转时使用（如跨课程的先修关系）。

## 搭建 3D 心智模型（MODELS）

每门课程一个「核心心智模型」场景，是课程知识体系的立体缩影：

```js
"课程id": {
  title: "场景标题",
  hint: "拖动旋转 · 滚轮缩放 · 点击金色标记点",
  camera: { yaw: 0.6, pitch: 0.35, dist: 9 },
  parts: [
    { id: "part-a", type: "box", pos: [0, 1, 0], size: [2, 1, 2], color: "#f5c451", label: "部件" }
  ],
  marks: [
    { id: "m1", at: [0, 1, 0], title: "锚点", body: "2-4 句", depth: "L2" }
  ]
}
```

规范：

1. **场景 = 课程的心智模型**：回答「学完这门课，脑子里应该留下什么立体图像」。
2. **部件用原语拼装**：`box`/`sphere`/`cylinder`/`cone`/`plane`/`ring`/`grid`/`line`/`arc`/`bowl`/`poly`；坐标 y 轴向上、地面 y=0，整体尺度控制在 ±4 以内。
3. **`part-` 前缀命名**，语义化（如 `part-vec-i`、`part-bowl`），供 `detail.focus` 引用。
4. **3–4 个锚点**：锚在关键部件上，内容与 marks 的深度递进一致。
5. **每张图解配置 `view`/`focus`**：让「一图一景」——切换图解时 3D 舞台自动转到对应机位并高亮部件。
6. **不追求写实**：几何示意优先，颜色沿用主题色板（金 `#f5c451`、青 `#2dd4bf`、蓝 `#60a5fa`、粉 `#f472b6`、绿 `#34d399`）。
7. 新增课程时必须同时提供 MODELS 场景（校验会给出警告）。

## 命名与文案规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 学校 id | 小写英文 / 缩写 | `mit`、`eth`、`nus` |
| 课程 id | `<学校>-<课程号>` | `stanford-cs229` |
| 章节 id | `c1`、`c2`…… | `c3` |
| 图解 id | `f01`、`f02`…… | `f07` |
| 标题 | 名词短语或结论句，≤ 24 字 | `从割线到切线` |
| caption | 一句话，≤ 40 字 | `切线斜率就是瞬时变化率` |
| tags | 2–4 个，避免泛词 | `["微积分","极限","导数"]` |
| updated | `YYYY-MM` | `2026-10` |

文案语气：

- 客观、克制，不用“最强”“必看”“颠覆”等营销词。
- 使用“本课程”“该章节”等书面表达；避免“我们”。
- 公式使用纯文本或 Unicode（如 `σ`、`∫`），不依赖 MathJax。
- 英文专有名词保留原拼写，中文译名首次出现时括注。

## 内容审核清单

维护者与评审者检查：

- [ ] 来源可靠，关键事实可核对；PR 中附来源链接。
- [ ] 课程归属的学校、学科、难度正确。
- [ ] 章节结构合理，图解与章节匹配。
- [ ] 图解类型与 `data` 形状匹配，渲染无溢出/遮挡。
- [ ] 文案无事实错误、错别字、机器翻译腔。
- [ ] 没有视频、整段教材复制或未授权图片。
- [ ] `npm run validate` 与 `npm run build` 通过。
- [ ] 首页统计、README 收录数量等派生信息已同步。
- [ ] 移动端与桌面端均检查。
- [ ] 新增/修改的文档与数据模型一致。

## 常见问题

**Q：课程没有公开课程号怎么办？**
A：`code` 可以使用课程名缩写（如 `CS101`），但 `id` 仍应保持稳定、可读。

**Q：一门课程横跨两个学科怎么办？**
A：选择最主要的学科作为 `discipline`，其他方向写入 `tags`。当前模型不支持多学科归属。

**Q：图解数据太长，渲染超出画布怎么办？**
A：拆分图解，或减少条目。渲染器只做展示，不应承担内容压缩。

**Q：可以引用外部图片吗？**
A：当前设计不使用图片，所有图解由 SVG 生成。如确需图片，必须先确认版权、存放位置与构建复制规则，并更新架构文档。

**Q：如何标记内容过期？**
A：修改 `updated` 为最近核对月份，并在 PR 中说明核对范围；不要只改日期而不核对内容。
